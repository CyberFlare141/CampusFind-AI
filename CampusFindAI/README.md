# CampusFind AI

CampusFind AI is an AI-assisted university lost-and-found platform that connects lost and found reports, supports role-based workflows, and will later provide smart matching, semantic search, verification, notifications, and analytics. This first repository pass intentionally keeps the domain and UI minimal while providing one real end-to-end authentication vertical slice that the team can copy as the project grows.

The project aligns with the CSE 3200 Software Development-V focus on ASP.NET/.NET web development, MS SQL Server, Entity Framework Code First, modern engineering tools, system architecture, code quality, deployment/versioning, and professional software documentation.

## Repository layout

```text

├── backend/
│   ├── Controllers/       # Thin HTTP/API endpoints
│   ├── Services/          # Business logic interfaces + implementations

│   │   └── Migrations/    # Generated by dotnet ef; intentionally empty
│   ├── Middleware/        # Global exception handling
│   ├── Extensions/        # DI, Identity, JWT and CORS registration
│   └── Program.cs         # Composition root
│
├── frontend/
│   ├── src/
│   │   ├── components/    # Shared UI components
│   │   ├── pages/         # Feature/page components
│   │   ├── services/      # API client + feature services
│   │   ├── context/       # AuthContext
│   │   ├── types/         # Shared TypeScript contracts
│   │   └── routes/        # React Router + ProtectedRoute
│   └── .env.example
│
└── README.md
```

## Where teammates should add work

| Area | Add new work here |
|---|---|
| Lost/found/claims API | `backend/Controllers`, `backend/Services`, `backend/Repositories`, `backend/DTOs` |
| Database entities | `backend/Models` + `backend/Data/ApplicationDbContext.cs` |
| EF migrations | `backend/Data/Migrations` via `dotnet ef` |
| Authentication/authorization | `backend/Services`, `backend/Extensions`, `backend/Models/ApplicationUser.cs` |
| AI matching/search | New services under `backend/Services` and corresponding DTOs/controllers later |
| React pages | `frontend/src/pages/<Feature>` |
| Shared React UI | `frontend/src/components` |
| API calls | `frontend/src/services` |
| Auth/session state | `frontend/src/context/AuthContext.tsx` |
| Routes/role guards | `frontend/src/routes` |

The CampusFind AI proposal identifies Student, Security Officer, and Administrator as the three internal roles and places matching/search, verification, QR claims, notifications, analytics, reputation, and audit logging in the broader product scope. Those features are intentionally not implemented in this first scaffold.

## Prerequisites

- .NET 10 SDK (latest .NET 10 patch at scaffold time: 10.0.11; .NET 10 is LTS).
- SQL Server available locally or remotely.
- Node.js 20.19+ or 22.12+ for current Vite; Node 22 LTS is a good team baseline.
- npm.

The frontend uses the current stable React/Vite ecosystem at scaffold time: React 19.2.8, Vite 8.2.2, React Router 7.18.2, Axios 1.19.0, and TypeScript 7.0.2. Vite 8 is the current stable major line.

## 2. Create and apply the initial EF Core migration

From the repository root:

```bash
dotnet tool install --global dotnet-ef --version 10.0.11

dotnet ef migrations add Init \
  --project backend/CampusFindAI.Api.csproj \
  --startup-project backend/CampusFindAI.Api.csproj \
  --output-dir Data/Migrations

dotnet ef database update \
  --project backend/CampusFindAI.Api.csproj \
  --startup-project backend/CampusFindAI.Api.csproj
```

PowerShell equivalent for the migration command:

```powershell
dotnet ef migrations add Init `
  --project backend/CampusFindAI.Api.csproj `
  --startup-project backend/CampusFindAI.Api.csproj `
  --output-dir Data/Migrations

dotnet ef database update `
  --project backend/CampusFindAI.Api.csproj `
  --startup-project backend/CampusFindAI.Api.csproj
```

EF Core's SQL Server provider and design-time package are the intended tooling for this Code First setup.

> **Important:** `appsettings*.json` contains dummy JWT secrets and local SQL Server placeholders. Replace them before any shared or production deployment. Do not commit real secrets.

## Auth vertical slice

The initial reference flow is:

```text
React LoginPage
    ↓
frontend/src/services/authService.ts
    ↓
Axios apiClient
    ↓
POST /api/auth/login
    ↓
AuthController
    ↓
IUserService → UserService
    ↓
ASP.NET Core Identity UserManager
    ↓
JWT generated
    ↓
React AuthContext stores token + user
    ↓
ProtectedRoute allows authenticated pages
```

Register follows the same backend service pattern. Self-registration creates a `Student`; Security Officer and Administrator provisioning can be added later through an administrative workflow rather than exposing privileged roles through public registration.

## Initial domain model

The scaffold contains one minimal model file for each requested domain concept: `ApplicationUser`, `Role`, `UserProfile`, `LostItem`, `FoundItem`, `Match`, `Claim`, `Building`, `Location`, `Category`, `Image`, `Notification`, `AuditLog`, `Badge`, `Reputation`, `ChatHistory`, `AIRequest`, and `Feedback`. The models are intentionally not the final production schema.

The submitted project ER diagram treats User as the hub and keeps LostItem and FoundItem as separate entities, with Images able to reference either side. This scaffold preserves that direction without attempting to reproduce the complete final schema in pass one.

## Team workflow note

To reduce merge conflicts for a 3–4 person team:

1. Keep controllers thin; put business rules in a service owned by the feature.
2. Keep EF queries in repositories rather than controllers.
3. Give each feature its own DTOs/services/repository methods as it grows.
4. Avoid editing shared files unless necessary, especially `Program.cs` and the central `ApplicationDbContext`.
5. Generate migrations deliberately and commit them as a coordinated database change.
6. Use small feature branches and pull requests; require at least one peer review.

This matches the course specification's emphasis on Git-based team workflow, documentation standards, structured peer code review, scalable architecture, code quality, and deployment/versioning.
